# 단어와 뜻의 출처

## Decisions

- AI가 낼 단어와 기본 뜻 카드(뜻풀이, 예문, 이모지)는 앱에 포함된 단어장에서 가져옵니다. 단어장은 직접 쓴 표준어이고 뜻풀이를 초등학생 눈높이로 다듬어 둡니다.
- 아이가 입력한 단어가 단어장에 없으면 서버가 표준국어대사전에서 확인합니다. 표준어(명사, 일반어)로 인정되면 그 단어를 낼 수 있고, 사전의 뜻풀이를 뜻 카드에 씁니다. 이때 그림은 기본 아이콘이고 예문은 쓰지 않습니다.
- 사전 확인은 서버를 거치고 인증 키는 서버에서만 읽습니다. 사전 응답은 파일이나 단어장에 저장하지 않고 실행 중 메모리에만 둡니다. 사전에 연결하지 못하면 아이의 기회를 쓰지 않습니다.
- 사전 자료를 보여 주는 화면에는 출처(국립국어원 표준국어대사전, CC BY-SA 2.0 KR)를 표시합니다.
- AI는 사전에서 단어를 고르지 않고 단어장에서만 고릅니다.

## Boundaries

- 사전에 없는 단어는 "사전에 없는 단어"로 거절합니다. 가까운 표준어를 제안하는 기능은 별도 작업입니다.
- 사전의 이미지, 소리, 발음 같은 멀티미디어 파일은 파일마다 이용 조건이 달라서 쓰지 않습니다.
- 출전이 표시된 용례(예문)는 원저작자가 저작권을 가지고 있어 쓰지 않습니다. 응답에서 출전 여부를 구분할 수 없는 사전의 예문은 쓰지 않습니다.
- 표준국어대사전을 입력 확인용으로 쓰기로 한 것이지, 제품의 기준 사전(`PRODUCT.md`의 미정 항목)을 확정한 것은 아닙니다.
- 한국어기초사전을 내려받아 단어장을 늘리는 일은 이 결정에 포함되지 않습니다. 서버가 복구되면 따로 정합니다.

## Why

표준국어대사전은 서버가 정상이고, 표준어 중심이라 "표준어가 아닌 단어는 통하지 않는다"는 앱의 경계를 지킬 수 있습니다. 하지만 난이도 정보가 없고 처음 100개 샘플의 대부분이 낯선 단어(사가, 사갈, 사갱 등)여서 AI가 낼 단어를 사전에서 고르면 로블록스의 "이상한 단어" 문제를 되풀이합니다. 그래서 AI는 쉬운 단어장에서만 고르고, 사전은 아이가 입력한 단어가 표준어인지 확인하고 뜻을 보여 주는 데만 씁니다. 응답을 저장하지 않으면 동일조건변경허락 라이선스의 배포 의무가 생기는 가공 데이터가 만들어지지 않고, 서버 장애를 아이의 불이익으로 만들지 않을 수 있습니다. 직접 쓴 단어장만으로는 아이가 아는 정상 단어가 너무 자주 거절되었습니다.

## Reconsider when

- 제품의 기준 사전이 정해질 때
- 한국어기초사전이 복구되어 난이도로 거른 단어장을 만들 수 있게 되었을 때
- 사전 확인이 느리거나 자주 실패한다는 근거, 또는 호출 한도를 넘는다는 근거가 생길 때
- 아이가 사전에 있는 부적절한 단어를 입력해 뜻을 보게 되는 일이 문제가 될 때
- 표준국어대사전 Open API 약관이나 라이선스 해석이 사전 응답을 일시적으로 기억하는 것과 맞지 않다고 확인될 때

## Still-rejected alternatives

- 표준국어대사전을 AI의 단어 공급원으로 쓰기: 난이도 정보가 없고 낯선 단어가 대부분입니다. 한자 병기와 붙임표를 거르는 휴리스틱을 써도 샘플의 절반 이상이 낯선 단어였고, 고유어만 골라도 사날, 사릅 같은 단어가 섞였습니다. 쉬운 단어를 고르는 기준(빈도 목록 등)이 생기면 다시 검토합니다.
- 우리말샘: 비규범, 방언, 북한어가 포함되어 이상한 단어가 통하는 문제를 다시 만들 수 있습니다.
- 네이버 사전 연동: 공식 국어사전 API를 찾지 못했고, 가장 가까운 백과사전 검색은 지식백과라 표준어 판정과 초등학생용 풀이에 맞지 않습니다. `developers.naver.com`의 현재 API 목록에서 국어사전 API가 확인되면 다시 검토합니다.
- `dict.naver.com` 화면 수집: 공식 API가 아니고 약관과 구조 변경 위험이 있습니다.
- 한국어기초사전을 지금 단어장의 공급원으로 쓰기: 난이도 등급이 있어 가장 알맞지만 서버가 오래 응답하지 않아 단어 수를 확인하지 못했습니다. 복구되면 다시 검토합니다.

## Evidence worth preserving

- 표준국어대사전 검색 API 스파이크(키 발급 후): 명사이면서 2–4음절인 단어가 "사"로 시작하는 것만 3,909개이고 "가" 2,373, "고" 2,700, "수" 3,168처럼 글자마다 수천 개입니다. "사"의 처음 100개는 모두 범주가 일반어이고 전문 분야 표시가 없었습니다. 응답 항목은 `word`, `sup_no`, `origin`, `pos`, `target_code`, `sense`(`definition`, `type`, `link`)입니다. 시작 글자 검색에서 "름", "륨", "늄", "녘", "륵", "릉"은 결과가 없었고 "믈", "귄"은 1개, "슴"은 3개, "뢰"는 4개, "끼"는 17개, "늘"은 24개, "쥐"는 94개였습니다. 상세 조회(`view.do`)는 빈 응답이어서 예문 구조와 출전 필드는 확인하지 못했습니다. `method` 같은 상세 변수는 `advanced=y`일 때만 적용됩니다.
- 표준국어대사전 Open API 안내 페이지: 인증 키(`key`) 필수, `req_type=json`으로 JSON 응답. 난이도 필터가 없습니다. 검색 변수로 `method`(exact, include, start, end, wildcard), `pos`, `letter_s`와 `letter_e`(음절 수), `type1`(단어, 구, 관용구, 속담), `type2`(고유어, 한자어, 외래어, 혼종어), `cat`(전문 분야), `num`(10–100), `start`(1–1000)가 있습니다. 호출 한도는 문서에 없습니다.
- 표준국어대사전 저작권 정책(사용자가 전문을 제공): 텍스트 자료는 크리에이티브 커먼즈 저작자표시-동일조건변경허락 2.0 대한민국 라이선스로 상업적 이용을 포함해 자유롭게 이용할 수 있습니다. 조건은 저작자 표시와, 자료를 변경해 만든 새 저작물의 동일 라이선스 배포입니다. 멀티미디어 파일은 파일마다 이용 조건이 따로이고, 출전이 있는 용례는 원저작자가 저작권을 소유하므로 원저작자의 이용 허락이 필요합니다. Open API 호출 자체의 약관(호출 한도 외의 조건, 응답 저장 가능 범위)은 확인하지 못했습니다.
- 한국어기초사전 검색 API: 인증 키 필수. 응답은 XML뿐이고 `req_type=json`은 무시됩니다. 응답 항목에 뜻풀이(`definition`)와 난이도 등급(`word_grade`)이 있고 예문은 없어 상세 조회가 따로 필요합니다. 시작 글자 검색, 품사, 음절 수 필터가 동작했고, "사"로 시작하는 단어는 필터 없이 1,518개, 명사이면서 2–4음절이면 370개였습니다. `level` 변수는 `1`로 보냈을 때 오류 211(Invalid level value)이 나서 올바른 형식을 찾지 못했습니다. 하루 호출 한도는 50,000건입니다. 확인 중 서버가 응답하지 않거나 연결이 끊기는 일이 반복되었고, 이후 사이트 자체가 열리지 않았습니다.
- 한국어기초사전 저작권 정책(사용자가 전문을 제공): 표준국어대사전과 같은 CC BY-SA 2.0 KR 조건입니다. 멀티미디어 파일은 파일마다 따로입니다.
- 네이버 오픈 API 목록(`naver.github.io/naver-openapi-guide`, 오래된 가이드): 검색 API 14종에 국어사전은 없고 백과사전(`/v1/search/encyc`)만 있습니다. `developers.naver.com`은 확인 당시 이 환경에서 열리지 않아 현재 목록은 직접 보지 못했습니다.
